# 客户侧展示验收流程

目标：以真实用户操作证明客户端具备美观、可理解且可靠的即时沟通体验。单个构建通过或接口返回成功不能替代完整业务验收；未验证项不记为通过。

## 环境与执行原则

- 同一仓库的 `frontend` 分支为客户端，`rebuild/kratos-gin` 分支为服务端。不要在历史副本中修复。
- 本地 Account `8001`、Chat `8002`、PostgreSQL、Redis；两服务 `/readyz` 必须为 200。桌面开发窗口与 file:// 发行构建均须验证。
- 使用独立合成测试账号甲、乙、丙，不清理用户聊天历史。大量消息只写入专用验收群。
- 用 Computer Use 完成客户端路径；API 可准备测试数据和检查契约，但不能替代 UI 验收。
- 默认每次桌面启动生成新 UUID，实例登录态与服务器设置独立。服务端同账号默认最多 3 个设备，`MAX_DEVICES_PER_USER=0` 可不限；实例数与同账号在线数不可混为一谈。
- 每次修复后：类型检查、构建、相关自动测试、对应 UI 用例、差异审查。后端接口/语义变动必须同步后端 `index.md`。只提交本轮改动，不带本地数据和无关配置。
